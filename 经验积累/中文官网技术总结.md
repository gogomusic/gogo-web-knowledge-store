# 中文官网（前端）技术总结

## 说明

中文官网（前端）包含**前台**、**后台**及**组件工厂**三个仓库。

1. **[前台](https://www.innosilicon.com.cn/)**：从后台读取网站数据并进行渲染
2. **后台**：配置官网的内容、新闻、表单等，官网前台的绝大多数内容都可以在后台配置，且配置后将立即生效。其中，内容（页面）由一个个组件搭建而成，这些组件由**组件工厂**打包并上传到后台
3. **组件工厂**：用于编写 React 组件，打包好之后，上传到后台的“组件商店”

本系统将所有页面内容抽象为原子化的组件，在后台使用低代码的方式进行配置

首先，开发人员根据设计师提供的设计稿，在组件工厂进行组件开发，打包后提交到后台的组件商店。运营人员根据需要，选择合适的组件拼装页面、绑定导航和 URL 然后发布，发布后将立即生效，用户刷新页面即可看到更新的内容。而不用重新打包、部署项目及重启服务器。另外，前台将根据后台配置的导航和 SEO 关键词等自动生成 SEO 元数据和站点地图（sitemap. xml），来实现 SEO 优化。

系统采用响应式开发模式，使用 Tailwindcss 进行 CSS 的编写。以保证移动端和 PC 端的浏览效果

系统还带有动态表单管理功能，负责人在后台可配置自定义的表单，并作为页面组件嵌入到页面中，并可设置表单有限期、权限、样式、邮箱模版等。并在前台增加了滑块验证码来防止恶意提交行为。

以上功能实现了网站上线后，内容更新无需打包和重新部署，不需要代码基础就可以配置页面。

## 技术栈

**前台**：Next. js 14.2、React、TypeScript、Tailwindcss/Scss、Ant Design v5/ProComponents、远程组件渲染、GSAP、wow.js、dompurify、Swiper、ahooks
**后台**：React、Ant Design v4/ProComponents、TypeScript、less、vditor、dompurify、ahooks、use-immer
**组件工厂**：vite、react、roolup、tailwindcss、GSAP、swiper

## 功能模块

### 后台

- **导航管理**：用于配置前台路由，可配置路由及其层级关系、URL、绑定页面、子路由类型及 SEO 配置等。前台根据这些配置，生成导航栏、前台路由和站点地图（sitemap. xml）。
- **页面管理**：本系统的核心功能，用户可通过低代码的方式进行页面布局完成页面配置，该模块包含以下功能：
	1. 页面配置：可配置页面的标题、SEO 关键词、描述等
	2. 组件选择：点击添加组件按钮，选择需要的组件添加到页面上，组件包括三大类：
		1. 内置组件：前台代码中内置的组件，是一些通用性最高或功能非常复杂，不会经常更改的组件。内置组件性能最好，并可使用 Next. js 的图片优化功能
		2. 自定义组件：自定义组件也是前台代码中内置的组件，不同的是其有较高的自定义功能。包括两种组件：
			1. 自定义组件：基于 Ueditor Plus 封装的 HTML 编辑器，用户可输入任意 HTML 内容，并通过 `dompurify` 防止 XSS 注入。启用高级模式后将禁用 `dompurify`，此时可输入 JS 脚本
			2. 自定义表单：可将自定义表单添加到页面上
		3. 组件商店组件：在组件工厂开发并打包，上传到组件商店的组件，这些组件由开发者或用户上传，可提供自定义配置项
	3. 组件调整：可对组件进行移动、删除、复制、隐藏
	4. 组件配置：组件提供各种配置项以满足用户的个性化需求，可更改组件的标题、图片、颜色等等；必要时，可编写 CSS 代码来覆盖组件默认样式
	5. 页面预览：预览已配置好的页面，并可预览 PC 和移动端的效果。该功能实际上是保存了一份临时页面配置，然后在后台嵌入了前台预览页的 iframe 实现
	6. 页面发布：页面发布后，需要在导航管理中绑定方可访问
- **组件商店**：用于上传和配置远程组件。开发者在组件工厂编写好组件代码后用 rollup 打包（生成 js 和 css），并将 js 和 css 代码上传到组件商店，并配置该组件的名称、图片资源、api、参数配置项、预览图、渲染方式（CSR 或 SSR）等。启用组件后，在页面管理中就可以添加该组件了
- **公共模块配置**：用于配置 Footer、版权信息等
- **文章管理**：管理文章内容，创建和发布文章。编辑器采用 Ueditor Plus。并可配置文章页面的 SEO 信息，也可以配置自定义的 URL
- **表单设计**
	可通过低代码的方式配置动态表单
	1. 表单布局：预设了横向或纵向布局。表单项可拖拽调整位置，可复制、删除等
	2. 表单配置：配置表单的各个属性，例如：文本框可配置默认值、placeholder、是否必填、正则校验，搜索方式等
	3. 表单预览
- **表单权限**：仅有权限的用户可查看表单及数据
- **数据收集**：展示表单数据填写情况，并根据表单结构动态生成搜索栏
- **需求管理**：查看前台需求表单的填写情况
- **邮件设置**：配置邮件服务器，测试服务器连通性
- **邮件模版**：可为系统邮件、表单配置邮件模版。编辑器采用 Ueditor Plus。如果是为表单配置邮件模版，可向编辑器插入表单中的字段
- **用户管理、角色管理**：基于 RBAC 的访问控制
- **菜单管理、登录日志、操作日志**：略

### 前台

- 动态路由生成、导航及页脚渲染
- 内容渲染：封装内置组件、远程组件渲染、响应式开发（兼容 PC 和移动端）、异常处理、动画和轮播图开发、自定义样式注入等
	1. 前台获取路由地址后，根据 URL 调用后台接口获取页面配置（JSON) 和 SEO 配置。如未找到，跳转到 404
	2. 根据 SEO 配置生成 SEO 相关标签：如页签标题、keywords、页面描述等
	3. 根据页面配置中的页面类型（固定、新闻、表单）执行不同的渲染策略
		1. 固定：直接根据页面配置中的组件配置等进行渲染，详见附录中的“远程组件渲染方法”
		2. 新闻：根据新闻 id 从后台获取新闻内容，进行渲染
		3. 表单：根据表单 id 从后台获取表单内容，进行渲染
- SEO 优化：SEO 相关元素生成、站点地图生成（sitemap. xml）
- 动态表单：渲染动态表单、响应式设计、滑块验证码验证等
- 防 XSS 攻击，用户输入过滤
- 兼容性处理，如兼容低版本浏览器、实现 Antd v5 服务端渲染等

#### Antd 服务端渲染及兼容性解决方案

可参照 Antd 官网的方案，示例如下：

```tsx
// AntdRegistry.tsx

// 如果你在 Next.js 当中使用了 App Router, 并使用 antd 作为页面组件库，为了让 antd 组件库在你的 Next.js 应用中能够更好的工作，提供更好的用户体验，你可以尝试使用下面的方式将 antd 首屏样式按需抽离并植入到 HTML 中，以避免页面闪动的情况。
// https://ant-design.antgroup.com/docs/react/use-with-next-cn#%E4%BD%BF%E7%94%A8-app-router
'use client';

import React from 'react';
// import { createCache, extractStyle, StyleProvider } from '@ant-design/cssinjs';
// 如果您使用的是 Next.js 14，请改用下面的导入。更多信息： https://github.com/ant-design/ant-design/issues/45567
import type Entity from '@ant-design/cssinjs/es/Cache';
import {
  createCache,
  extractStyle,
  legacyLogicalPropertiesTransformer,
  StyleProvider,
} from '@ant-design/cssinjs/es';
import { useServerInsertedHTML } from 'next/navigation';

const StyledComponentsRegistry = ({ children }: React.PropsWithChildren) => {
  const cache = React.useMemo<Entity>(() => createCache(), []);
  const isServerInserted = React.useRef<boolean>(false);
  useServerInsertedHTML(() => {
    // 避免 css 重复插入
    if (isServerInserted.current) {
      return;
    }
    isServerInserted.current = true;
    return (
      <style
        id="antd"
        dangerouslySetInnerHTML={{ __html: extractStyle(cache, true) }}
      />
    );
  });
  return (
    <StyleProvider
      hashPriority="high"
      cache={cache}
      transformers={[legacyLogicalPropertiesTransformer]}
    >
      {children}
    </StyleProvider>
  );
};

export default StyledComponentsRegistry;
```

在最外层 `layout.tsx` 中导入此组件，并使用其包裹 `children` 即可

#### 远程组件渲染方法

##### 1. 远程组件渲染过程

1. 读取页面配置，其中，远程组件是一个数组，包含各个组件的 id、配置等
2. 遍历远程组件的数组，根据远程组件 id，由 Next 服务器向后端请求组件内容（js 和 css）（通过 fetch 的缓存功能，组件如无更新，此请求将直接使用缓存的内容）。获取的 js 内容将通过 `React.lazy` 方法加载为 React 组件，而 css 将通过 `style` 标签插入 HTML 中
3. 判断组件是否需要获取额外的数据，如果需要，继续请求 API 接口获取组件需要的数据
4. 判断组件类型及渲染方式（CSR 或 SSR），开始渲染组件，并将上一步获取的数据及用户自定义的配置作为 prop 注入组件中
	1. 向 HTML 中注入组件 css，包括组件自带的 css 和用户自定义的 css
	2. 渲染方式如果是服务器渲染（SSR），由服务端生成 HTML 直接渲染在页面上
	3. 渲染方式如果是服务器渲染（CSR），由于代码中含有 hook 或 js 交互事件等，其将在客户端渲染
5. 完成页面渲染

##### 2. 编写和打包远程组件

远程组件即为普通的 React 组件，编写完成后，通过 `rollup` 打包为 `CommonJS` 模块（会输出 js 和 css 文件）。`rollup` 配置如下：

```js
// rollup.config.js

import terser from "@rollup/plugin-terser";
import typescript from "rollup-plugin-typescript2";
import babel from "@rollup/plugin-babel";
import fs from "fs";
import postcss from "rollup-plugin-postcss";
import tailwindcss from "tailwindcss";
import autoprefixer from "autoprefixer";
import image from "@rollup/plugin-image";
import args from "yargs";
import lodash from "lodash";
import tailwindConfig from "./tailwind.config.js";

const argv = args(process.argv.slice(2)).argv;

let components = fs.readdirSync("./src/components");

if (argv.filename) components = [`${argv.filename}.tsx`];

const removeFileExtension = (filename) => {
  return filename.replace(/\..*/, "");
};

function generateConfig(filename) {
  const _config = lodash.cloneDeep(tailwindConfig);
  _config.content = [`./src/components/${filename}`];
  return _config;
}

const config = components.map((filename) => {
  return {
    input: `./src/components/${filename}`,
    output: {
      file: `finally/${removeFileExtension(filename)}.js`,
      format: "cjs",
    },
    plugins: [
      typescript(),
      postcss({
        extract: `${removeFileExtension(filename)}.css`, // 从 bundle 中提取 CSS 保存到单独的文件
        minimize: true, // 压缩 CSS
        plugins: [
          autoprefixer(),
          tailwindcss({ config: generateConfig(filename) }),
          function (root) {
            root.walkRules((rule) => {
              rule.selectors = rule.selectors.map((selector) => {
                if (/^\d|^from$|^to$/.test(selector)) {
                  return selector;
                }
                return `.${removeFileExtension(filename)} ${selector}`;
              });
            });
          },
        ],
      }),
      babel({
        babelHelpers: "bundled",
        exclude: "node_modules/**",
      }),
      terser(),
      image(),
    ],
    options: {
      compress: {
        /** 打包时是否剔除console语句 */
        drop_console: true,
      },
    },
    external: [//不打包的依赖，这些依赖将由前台提供
      "react",
      "react-dom",
      "clsx",
      "antd",
      "swiper/element/bundle",
      "dompurify",
      "lodash",
      "react-toastify",
      "gsap",
      "dayjs",
    ],
  };
});

export default config;
```

打包命令如下：

```json
"build:all": "rollup --config ./rollup.config.js",
"build:one": "rollup --config ./rollup.config.js --filename"
```

##### 3. 渲染远程组件

将打包后的远程组件上传到后台的组件商店，完成组件配置和页面配置后，即可在前台渲染。

核心代码如下，以下是服务端渲染组件的代码，客户端的与其大致相同：

```ts
// packages.server
// 用于向远程组件注入依赖

import "server-only";

import React from "react";
import clsx from "clsx";
import * as antd from "antd";
import * as swiper from "swiper/element/bundle";
import { sanitizeServer } from "@/utils/sanitize/server";
import lodash from "lodash";
import * as toastify from "react-toastify";

const packages: any = {
  react: React,
  clsx,
  antd,
  "swiper/element/bundle": swiper,
  dompurify: { sanitize: sanitizeServer },
  lodash,
  "react-toastify": toastify,
};

export default packages;

```

```tsx
// RenderServerRemoteWidget.tsx

import { Suspense, lazy, memo } from "react";
import packages from "./packages.server";
import Loading from "@/loading";

type ComponentProps = {
  data: { css: string; script: string; status: 0 | 1; api: string | undefined };
  children?: React.ReactNode;
  props?: Record<string, any> & {
    /** 组件的id，用于自定义组件样式时引用元素 */
    id: string;
  };
};

const loadRemoteComponent = async (script: string) => {
  const _module = { exports: {} };
  const exports = {};
  const require = (name: string) => {
    return packages[name];
  };
  try {
    const func = new Function("module", "exports", "require", script);
    func(_module, exports, require);
    return { default: _module.exports } as any;
  } catch {
    return import("./WidgetLoadingError");
  }
};

/** 由服务端渲染远程组件 */
const RemoteComponent: React.FC<ComponentProps> = async ({
  data,
  children,
  props,
}) => {
  const Component = lazy(() => loadRemoteComponent(data?.script));
  return (
    <Suspense
      fallback={
        <div className="w-full py-5 mx-auto">
          <Loading />
        </div>
      }
    >
      <>
        {data?.css && (
          <style
            dangerouslySetInnerHTML={{ __html: data.css ? data.css : "" }}
            suppressHydrationWarning
          ></style>
        )}
        <Component {...props}>{children}</Component>
      </>
    </Suspense>
  );
};

export default memo(RemoteComponent);

```

这段代码定义了一个 React 组件 RemoteComponent，用于服务端渲染远程加载的组件。它的核心功能是根据传入的脚本字符串动态加载组件，并在加载过程中显示一个加载动画。

首先，ComponentProps 类型定义了组件的属性，包括远程组件的样式（css）、脚本（script）、状态（status）、API 地址（api），以及可选的子节点和其他自定义属性（如 id）。

loadRemoteComponent 是一个异步函数，负责将传入的脚本字符串作为模块执行。它通过 new Function 创建一个新的函数作用域，模拟 CommonJS 的 module, exports, require，从而实现脚本的隔离和依赖注入。如果脚本执行失败，则回退到加载错误组件 WidgetLoadingError。

在 RemoteComponent 组件内部，使用 React 的 lazy 和 Suspense 实现异步加载远程组件。加载过程中会显示一个自定义的 Loading 组件作为占位。加载完成后，如果有样式字符串，则通过 dangerouslySetInnerHTML 动态插入样式。最后渲染远程组件，并传递所有 props 和 children。
